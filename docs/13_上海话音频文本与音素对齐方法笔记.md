# 上海话音频、文本与音素强制对齐方法笔记

> 历史方法调查；实际已采用无调音素CTC微调，当前结果见19号公开进展报告。

核验日期：2026-09-10。文件位置遵循项目 README：本文保存在 `docs/`；官方文档、模型卡和源码缓存保存在 `generated/recording_11_20260909/tone_pilot/references/alignment/`。本文是方法调查与下一步方案，不表示已经完成新模型安装、上海话读音审定或对齐准确率验收。

**当前最可行的路线是：先核准单人短音频及实际说出的文字，做一小批人工边界基准；随后以经核准的上海话读音词典和兼容声学模型试验 MFA 音素对齐。** 现有 Qwen 字时间戳可作候选，但无法通过把汉字换成 IPA 就自动变成可靠音素对齐。普通话模型、支持多语言的模型、能识别吴语的 ASR 模型，都不等于已验证的上海话强制对齐模型。

## 1. 四个常被混在一起的步骤

| 步骤 | 输入 → 输出 | 是否得到音频时间 |
|---|---|---|
| ASR 自动转写 | 音频 → 推测文字 | 可能给句时间，不能自动视为准确字/音素边界。 |
| G2P / 发音词典 | 文字 → 一个或多个读音序列 | 不听音频，不产生对齐时间。 |
| 强制对齐 | 音频 + 已知文本/读音 + 声学模型 → 对应区间 | 是；但依赖文本确实被说出、模型认识这些声音和标签。 |
| 层级回连 | 音素区间 + 读音结构映射 → 音节/汉字区间 | 不重新识音，依赖映射关系正确。 |

字的区间错误时，F0 算得再准确也会配给相邻字。字时间有序、无重叠、位于句范围内，只是结构检查；几个汉字同时得到零时长，更应视作对齐失败信号。不能用平均分配、按字数均分或扩大零时长的方法制造“已对齐”。

“音素”一词在工具文档中常泛指 acoustic phone 标签，不一定与语言学的音位一一对应。一个 IPA 音可以由多个 Unicode 字符写成，一个声学模型也可能把韵母整体看作一个标签。必须记录实际 phone set，而不是只写“使用 IPA”。

## 2. 常用方案比较

| 方法 | 如何对齐 | 用户能否指定读音 | 对本项目的结论 |
|---|---|---|---|
| MFA / Kaldi 词典式强制对齐 | 文字经词典展开为 phone 序列，声学模型约束其在音频中的路径 | 可以，通过词典、发音变体及部分规则配置 | 最符合“文本→音素→音频”的需求；需要兼容上海话的读音和声学资源。 |
| CTC 对齐 | 声学模型产生逐帧 token 概率，通过动态规划寻找符合目标序列的时间路径 | 只有模型输出单位就是 phones 且接口支持时，才能直接给 phone 序列 | CTC 是算法框架，既可对齐汉字/字母，也可对齐音素；不是天然的 IPA 对齐器。 |
| WhisperX | 先获得文本，再用语言专属 wav2vec2 CTC 模型细化时间 | 通常使用所选模型的字符标签，没有 MFA 式可替换读音词典 | 可作独立对照；官方默认中文模型不是已验证的吴语模型。 |
| Qwen3-ForcedAligner | 音频和文本共同输入，预测各文本单位起止时间 | 公开封装接口是 `audio, text, language`，没有 phone/lexicon 参数 | 保留为字级候选；不能声称能将任意 IPA 串作为语音学音素正确对齐。 |
| Praat 人工/辅助标注 | 波形、声谱与听感结合，人工确认边界 | 可以直接记录实际读音 | 是小规模可靠参考的必要来源；F0 起点不是所有音节的起点。 |

以上结论基于 MFA 官方工作流、WhisperX README 与对齐源码、Qwen 官方 README 与封装源码，以及 PyTorch 的 CTC 对齐教程。[1–8]

### MFA 的具体机制和资源

MFA 的传统命令输入是录音语料目录、发音词典、预训练声学模型与输出目录。输出可为带词层和 phone 层的 TextGrid，也支持 JSON/CSV。这里的词典是“文本 token → 模型 phone 序列”的映射。[1][2]

词典格式要求不同字段以 tab 分隔，发音内部以空格分隔。示意如下，`P1 P2` 只是模型 phone 名称占位，不是本项目的真实上海话读音：

```text
字词甲<TAB>P1 P2 P3
字词甲<TAB>P1 P4
字词乙<TAB>P5 P6
```

同一个词可给多个实际可能的发音；词典外词会造成 OOV 问题，应查看 `oovs_found.txt` 和逐句 OOV 报告。词典增加发音并不自动给声学模型增加识别新音的能力。

已核验的 **Mandarin MFA acoustic model v3.0.0** 模型卡明确规定：它用于 Mandarin Chinese，使用 Mandarin 的 MFA phone set；可以增加词的发音，前提是**不引入新的 phones**。其训练材料为低噪声朗读。由此不能把上海话全部浊音、入声、元音和发声态差异粗略改写成看似接近的普通话标签，然后宣布已获得上海话对齐支持。[3]

MFA 的程序本身允许用户训练其他语言的模型，但“软件可扩展”与“已下载模型支持吴语”是两件事。应逐项核对声学模型 `phones`、词典 phone set、声调标签、音素组合/拆分方式和录音域，再决定是否能迁移。

### WhisperX 与 CTC 的“音素对齐”表述需看实际模型

WhisperX README 使用了 phoneme alignment 的描述，但已查源码实际构造 `align_dictionary`，逐字符查 CTC 模型词表，再进行 trellis/backtrack。因此实际输出单位由模型标签决定，不能单凭该描述认定它先做 IPA G2P。[6]

截至核验日，源码默认中文 `zh` 指向 `jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn`，未列 `wuu`。README 也明确要求相应语言的对齐模型，并提示重叠说话效果不佳。最新版源码对未知字符有 wildcard 处理，而 README 仍保留部分词无法获得时间的提醒；安装版本和未知字符处理必须记录，wildcard 有时间也不意味着该音被准确识别。

CTC 对齐可概括为：给定声学帧 \(X=(x_1,\dots,x_T)\) 和目标 token 序列 \(Y\)，在符合 CTC blank/重复折叠规则的路径中寻找高概率路径：

\[
\pi^*=\arg\max_{\pi:\mathcal B(\pi)=Y}\sum_t\log P(\pi_t\mid X).
\]

若模型词表是汉字，Y 必须是相应汉字标签；若词表是拉丁字母，Y 是对应字母；只有训练输出标签是 phones 的模型，Y 才能是该模型的 phone 序列。将未知 IPA 强行替换成近似 ASCII，只是改变目标标签，不是解决声学匹配。

PyTorch 的 MMS_FA 多语种教程提供另一种候选，但其文本前处理采用模型要求的规范化/罗马化，不能把通用 uroman 的汉字结果当作经上海话核验的 G2P。多语言训练可以帮助迁移，仍需核实训练语言、实际标签、上海话读音和边界测试。所查旧 `torchaudio.functional.forced_align` 教程注明相关 API 在 2.8 弃用、2.9 移除；照旧代码重建时必须固定兼容版本或另选仍维护的实现，不能覆盖当前 ASR 环境试错。[8]

### Qwen 是否能接收音素

Qwen3-ASR 官方模型表分别列出了 ASR 和 ForcedAligner：ASR 的方言栏包含 Wu language；ForcedAligner 列出 Chinese、English、Cantonese 等 11 种语言，方言栏为 `--`。**不能把 ASR 的吴语识别范围转移到独立 ForcedAligner 上。**[7]

源码中 `align(audio, text, language)` 将文本交给 `Qwen3ForceAlignProcessor.encode_timestamp`。清洗器只保留 Unicode 字母类 L、数字类 N 和撇号；IPA 的一些组合附加符号会被剥除，例如表示成音节、清化等的组合符号属于 M 类。剩余音标也仍作为文本 token 处理。官方“arbitrary units”描述不能替代“支持任意 IPA phone set”的验证；公开示例展示的是词/汉字时间，不是音素词典接口。[7]

## 3. 上海话读音层需要怎样准备

先保存两种互相关联、但目的不同的文字层：

- **用户整理稿**：保留用户最终想呈现的文字，不擅自恢复已删除内容。
- **对齐用逐字实录及排除表**：只为解释音频中实际存在的声音，标明重复、停顿词、省略、笑声、不可辨内容和用户删节区域。被删去的语音必须切开或明确排除，不能让前后保留字跨过它强行对齐。

上海话发音词典需人工核准上下文中的实际读音。G2P 只能给候选读音，特别要处理同形异读、文白读、轻化、变调域内的读音变体、连读省音和合音。普通话拼音不是上海话音素转写；模型提供 Chinese tokenizer/G2P 也不能自动替代吴语规则。

建议将读音结构拆成以下字段：

```text
utterance_id, token_id, char_ids, token_text,
lexical_pronunciation, surface_pronunciation,
syllable_ids, phone_sequence, phone_to_syllable,
pronunciation_source, pronunciation_review_status
```

声调标签由模型设计决定。无调 phone 模型可先用于分段，再在音节韵核测 F0；有调 phone 模型必须满足其既定标签集。不要拿当前待验证的五度标记作为强制对齐读音约束，否则用先验调值决定边界、再用边界证明调值，会形成循环。对省音或合音允许一字缺失、多字共享音节等关系，不能坚持每字必须占一段有声帧。

优先保留词级词典和显式的 phone→syllable 映射：上海话的多字词读音未必等于逐字孤立读音简单拼接。为对齐方便而逐字加空格，也不能改变真实的连读关系。必要时可使用稳定的实例 token ID 指向已核准的上下文发音，旁表保存其原文字与汉字 ID；这是一种显式管理策略，实施时需检查工具不会自动改写 token。

## 4. 适配与训练需要什么

**直接使用预训练模型**：需要干净音频、与音频一致的逐句文本、speaker/轨道来源、完整词典及模型 phone set 兼容检查；另需一批人工边界才能评估。即使成功运行，也先标为实验对照。

**MFA 适配**：官方流程先用旧模型对齐新数据，再用新数据更新 GMM 均值；可加入人工或已核验 reference alignments，跳过这些文件的初始自动对齐。[4] 因此，当前已发现漂移和零时长的结果不能未经复核就全部用于适配。适配不是自动发现新的上海话 phones；若现有模型缺关键音，需要重设音系/模型资源，不能靠均值更新补全。

**MFA 从头训练**：需要音频、精确句段文本、发音词典及足够的相关音类覆盖；不要求一开始全语料都有人工作出的音素边界，但人工参考对模型质量和评估很有价值。官方建议用实际数据比较训练、适配和直接使用预训练模型，并未承诺某个小时数必然够用。[5] 本项目的一小时录音还存在多人、删节与弱串音，不应直接算作“一小时干净上海话训练集”。

**训练/微调 phone CTC**：需要语音与匹配的 phone 序列，确定统一词表、blank、转写规则和足够音类覆盖；CTC 训练本身可以不依赖逐帧边界，评估仍需要独立人工边界。通用多语种表征模型可以作为初始化，但应核实最终输出头是否有可用 phones，而不能只看模型名称中的 multilingual。

如果只有普通话模型，短期可把它作为局限明确的对照试验，但不要丢弃上海话的关键对立来迁就模型。若兼容性检查不通过，先人工做小规模目标音节边界，再扩充上海话读音词典和匹配训练材料，比把不兼容输出直接铺到593段更有依据。

## 5. 音素如何回到音节、汉字及五度标记

对齐前就建立 `phone_id → syllable_id → char_id(s)`，同时保留 `token_id`。假设音节 j 的发音映射到连续 phones \(p_a,\dots,p_b\)，其整体边界候选为：

\[
s_j=\min_{i=a}^b s_i,\qquad e_j=\max_{i=a}^b e_i.
\]

这一步必须使用实际选择的发音变体，不能仅看每字拼音长度来分配。词内含静音或对齐异常时先标问题，不能把所有中间间隔都无条件吞入音节。

需要分清音节边界和承载声调的区间：清塞音闭塞、送气和清擦音也属于音节的一部分，但常没有可靠 F0。五度曲线应在经核验的韵核/响音或有声区间内测量，不能反过来把第一帧有声点等同于整字开头。

切片局部时间回连原轨道时使用实际物理起点：

\[
t_{global}=t_{clip\_origin}+t_{local}.
\]

已有593句切片前后含50 ms上下文；首轮五度试验片段则含250 ms上下文。必须分别读取实际 origin，不能混用字幕起点或统一加减固定值。段内 phone 和字映射采用半开区间 `[start,end)`，原始音轨和时间线偏移也应核对。

最终每个字至少分别保存：文字来源状态、读音审核状态、phone 对齐状态、音节边界审核状态、F0质量、五度审核状态。成功输出 phone 边界不应自动把这些字段全部改为“完成”。

## 6. 建议的下一轮本地试验

1. **先修输入对应关系**：核对音轨1的实际说话人、原工程时间线和片段 origin；从当前错位片段开始，选单人、无重叠、字数少的2–8秒片段，保留足够但已知的上下文。只有时间坐标整体错位时才修统一偏移；不将局部伸缩问题一律当成偏移。
2. **建立20–30个短片段的人工参考**：逐句确认文字和上海话读音，至少标音节边界及声调测量区。此数量是工程起步建议，不是统计学充分性保证；保留一部分未用于调参或适配的片段。
3. **并排比较候选**：现有 Qwen 字对齐作为基线；如本机资源允许，加入语言模型身份明确的 CTC/WhisperX 对照；MFA 只有在 phone set 检查通过后才使用上海话词典试对齐。每种方法使用同一音频和实录，分别保存结果。
4. **记录实质性误差**：比较人工边界的绝对误差、中位数/90或95分位、落在20/50/100 ms内的比例、漏字/多字、零时长、跨字错配和需人工修正数量。不能只用文件成功率或句级文字相似度评价。
5. **按结果决定训练**：若 MFA 的相近音素候选在人工集上可用，再用核验参考做适配；若关键 phones 不覆盖或误差集中于上海话特有读音，则先补资源或训练。没有证据之前不批量替换原593段时间。
6. **最后重算字调对应**：待音节/字边界通过复核后，用原全轨归一化参数重新采样 F0。对齐改动通常不需要重新定义整轨五度 Hz 区间，需改变的是每字取样的时间范围。

本轮未执行这些新模型实验，也没有宣称查到了可直接用于本录音的成熟上海话 MFA 模型。调查结论是：音素路线确实可行，但收益来自**正确上海话读音 + 兼容声学标签 + 对齐质量验证**，不是来自把文字形式换成音标本身。

## 7. 已核验的官方来源

1. **MFA Pronunciation dictionary format**：[官方文档](https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/dictionary.html)。核验 tab/space 格式、发音变体、OOV 与非语音标记。缓存 `mfa_dictionary.html/.txt`。
2. **MFA Align with an acoustic model**：[官方工作流](https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/workflows/alignment.html)。核验 corpus+dictionary+acoustic model 输入、输出格式和 reference evaluation；MFA 3.4起新增HF模型打包方式，执行时要锁定版本，本文不把旧命令当永久接口。缓存 `mfa_align.html/.txt`。
3. **Mandarin MFA acoustic model v3.0.0**：[官方模型卡](https://mfa-models.readthedocs.io/en/latest/acoustic/Mandarin/Mandarin%20MFA%20acoustic%20model%20v3_0_0.html)。核验“Mandarin”“不能引入新phones”和低噪朗读训练范围。缓存 `mfa_mandarin.html/.txt`。
4. **MFA Adapt acoustic model to new data**：[官方工作流](https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/workflows/adapt_acoustic_model.html)。核验先对齐再更新GMM均值、允许人工reference。缓存 `mfa_adapt.html/.txt`。
5. **MFA Train a new acoustic model**：[官方工作流](https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/workflows/train_acoustic_model.html)；**Generate pronunciations**：[G2P工作流](https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/workflows/dictionary_generating.html)。区分声学训练与文字→发音生成。缓存 `mfa_train.*`、`mfa_g2p.*`。
6. **WhisperX**：[官方README](https://github.com/m-bain/whisperX/blob/main/README.md)与[alignment.py](https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py)。核验语言特定模型、默认zh模型、字符词表和CTC路径；缓存 `whisperx_readme.*`、`whisperx_alignment_code.py/.txt`。由于main分支会变化，应以缓存和具体安装版本重现。
7. **Qwen3-ASR / Qwen3-ForcedAligner**：[官方README](https://github.com/QwenLM/Qwen3-ASR/blob/main/README.md)与[强制对齐封装源码](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_forced_aligner.py)。核验ASR与aligner不同语言范围、接口签名和文本清洗规则；缓存 `qwen3_readme.*`、`qwen3_aligner_code.py/.txt`。
8. **PyTorch Audio CTC alignment**：[CTC教程](https://docs.pytorch.org/audio/stable/tutorials/ctc_forced_alignment_api_tutorial.html)与[多语种教程](https://docs.pytorch.org/audio/stable/tutorials/forced_alignment_for_multilingual_data_tutorial.html)。核验目标标签需要与模型训练一致、多语种前处理及旧API生命周期；缓存 `torchaudio_ctc.*`、`multilingual_alignment.*`。
