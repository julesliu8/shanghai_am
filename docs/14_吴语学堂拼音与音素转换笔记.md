# 吴语学堂拼音与音素转换笔记

核验日期：2026-09-10。本文针对用户指定的 `shanghai_app/processed_results.csv` 最后一列。原件不改写；方法笔记放在 `docs/`，网页、方案文本、官网读音图像和本地只读审计保存在 `generated/recording_11_20260909/tone_pilot/references/wugniu/`。

**主要结论：最后一列的声韵拼写可按吴语学堂式上海话方案解析，但它的数字后缀不能全部按官网调类号解释。** 绝大多数词条使用 `22、33、44、55、21` 等调值形式，另有少量行仍保留 `6、7、8` 等调类号。应把声韵拼写和原始声调后缀分开保存，再依据具体来源判断；不能把词典调值当成本次录音实际测得的五度值。

## 1. 本轮查到了什么方案

吴语学堂官网 `wugniu.com` 的字音查询区分“上海闲话”“上海闲话（老）”和多种郊区方言；参考书目把默认上海条目对应到许宝华、汤珍珠《上海市区方言志》（1988），把上海老派对应到陶寰、高昕《上海老派方言同音字汇》（2018）。因此“上海话吴拼”必须带具体版本/口音，不能泛指任何年代的上海话。[1]

本轮读取的完整拼音表来自 `NGLI/rime-wugniu_zaonhe` 的《音系及拼音方案》wiki。该项目 README 明确自称采用“吴语学堂式拼音”，同时区分上海中派、上海老派和松江；其上海 schema 列吴飞得等参与者、版本 `0.37`，并链接吴语学堂官网。[2] 本文将它作为**公开方案整理来源**，并用官网多个实际查询的 IPA/吴拼并列结果交叉核验，不把第三方代码仓库自动称作官网标准发布页。

另一个容易混淆的仓库 `rime/rime-wugniu` 自述使用《吴语拉丁式注音法》，不能只看名字含 `wugniu` 就套用它的规则。NGLI 项目虽兼容吴语协会式输入，但输入法的容错、模糊音和简拼规则也不等于音素转换规则。[2][3]

官网当前的 IPA 和吴拼列是 SVG 路径，不是普通 HTML 文本。本轮已将原 SVG 放大成图并逐项读取，缓存 `official_lookup_visual.png`、`official_lookup_more.png`；不是靠空白文本抽取臆测。音频文件名只辅助核对拼写，IPA 值由页面图形读取。

## 2. 上海中派声母对照

下表转录公开方案中“上海（中派）”部分；同一个拼写在老派或松江表中可能不同。方括号保留该方案的符号，不表示本轮录音已逐音听辨验证。[2]

| 拼写 | 方案音值 | 转换注意 |
|---|---|---|
| p / ph / b | [p] / [pʰ] / [b] | `ph` 是送气塞音，不拆成 [p]+[h]。 |
| t / th / d | [t] / [tʰ] / [d] | 同上，送气是整体音的区别。 |
| k / kh / g | [k] / [kʰ] / [ɡ] | 不能沿用普通话拼音 g/k 的解释。 |
| ts / tsh | [ts] / [tsʰ] | 塞擦音为模型中的一个还是多个 phones，需另看模型标签。 |
| c / ch / j | [tɕ] / [tɕʰ] / [dʑ] | `j` 不是 IPA [j]；`ch` 不是普通话卷舌声母。 |
| f / v | [f] / [v] | 老派表相应列作 [ɸ]/[β]，不要混用。 |
| s / z | [s] / [z] | `z` 不是普通话拼音 z 的 [ts]。 |
| sh / zh | [ɕ] / [ʑ] | 不是普通话 [ʂ]/[ʐ]；方案把 zh 加括号，并提示尖团分合差异。 |
| m / n / l | [m] / [n] / [l] | `n` 为普通鼻音；作为独立韵母时另见成音节项。 |
| gn | [ȵ] | 与 `ng` 不同；不能拆成 [ɡ]+[n]。映到模型常用 [ɲ] 等标签前需记录所作近似。 |
| ng | [ŋ] | 与 `gn` 不同；独立音节 `ng` 另作成音节鼻音分析。 |
| mh / nh / lh / kn / nk | [ʔm] / [ʔn] / [ʔl] / [ʔȵ] / [ʔŋ] | 方案“紧喉”系列；不能直接按去掉 h/k 后的普通鼻/边音处理。 |
| h | [h] | 与 `gh` 区别。 |
| gh | [ɦ] | 不是 [ɡ]+[h]；随后接的韵母可改写成 y/w 起首。 |
| 零声母 | 方案记作 ∅ | 是否在声学模型中显式放入声门成分，不能由拼写自行决定。 |

已用官网核对：`其 ji6` 的 IPA 为 [dʑi²³]，`斜 zhia6` 为 [ʑiᴀ²³]，`许 shiu5` 为 [ɕy³⁴]，`学`白读 `ghoq8` 为 [ɦoʔ¹²]，`人`白读 `gnin6` 为 [ȵin²³]。这些例子直接支持 j、zh、sh、gh、gn 的区别。[1]

方案中的尖团说明不能简化为“所有 s/z 都转换为 sh/zh”。输入法源码的 `derive` 允许兼容某些合流或模糊输入，这只是让用户更容易打字，不证明每个说话人都实际合流。

### gh、y、w 的条件拼写

公开方案规定：声母 [ɦ] 接 i 韵母或 i 介音时写 `yi` 或 `y-`；接 iu 韵母/介音时写 `yu-`；接 u 韵母或 u 介音时写 `wu` 或 `w-`；其余写 `gh`。[2]

例如官网“鱼”文读 `yu6` 对应 [ɦy²³]；“学”文读 `yaq8` 对应 [ɦiᴀʔ¹²]，白读 `ghoq8` 对应 [ɦoʔ¹²]。所以不能将字符串开头的 `y` 一律转换成 IPA [y] 或 [j]。**韵母 y 的 [ɿ] 与起首 y 的条件拼写是不同情况。**

## 3. 上海中派韵母与 q 的对照

以下是公开方案列出的上海中派韵母，保留其 [ᴀ]、[ᴇ] 等原记法；它们与具体模型的标签仍需单独映射。[2]

| 类别 | 已核的拼写 → 方案音值 |
|---|---|
| 高元音与舌尖元音 | `y`→[ɿ]；`i`→[i]；`u`→[u]；`iu`→[y] |
| a 系 | `a`→[ᴀ]；`ia`→[iᴀ]；`ua`→[uᴀ] |
| o / au 系 | `o`→[o]；`au`→[ɔ]；`iau`→[iɔ] |
| eu 系 | `eu`→[ɤ]；`ieu`→[iɤ] |
| e 系 | `e`→[ᴇ]；`ie`→[iᴇ]；`ue`→[uᴇ] |
| oe 系 | `oe`→[ø]；`uoe`→[uø]；`ioe`→[yø] |
| an 系 | `an`→[ã]；`ian`→[iã]；`uan`→[uã] |
| aon 系 | `aon`→[ɑ̃]；`iaon`→[iɑ̃]；`uaon`→[uɑ̃] |
| en 系 | `en`→[ən]；`in`→[in]；`uen`→[uən]；`iun`→[yn] |
| on 系 | `on`→[oŋ]；`ion`→[ioŋ] |
| aq 系 | `aq`→[ᴀʔ]；`iaq`→[iᴀʔ]；`uaq`→[uᴀʔ] |
| oq 系 | `oq`→[oʔ]；`ioq`→[ioʔ] |
| eq / iq 系 | `eq`→[əʔ]；`iq`→[iɪʔ]；`ueq`→[uəʔ]；`iuq`→[yɪʔ] |
| er | `er`→[əl]，不是普通话儿化韵 [ɚ] |
| 成音节鼻音 | `m`→[m̩]；`n`→[n̩]；`ng`→[ŋ̍]（成音节标记依源表保留） |

`q` 在这些入声韵尾中表示声门塞尾 [ʔ]，不能按普通话 q 读作 [tɕʰ]，也不能按 IPA 字符 q 读作小舌塞音。`iq`、`iuq` 具有表中指定的元音部分，不能只把任意词尾 q 换成 [ʔ] 后宣称整个韵母已正确转换。

特别容易误转的组合如下：

- `iu` 是 [y]，不是按两个字母逐个读成 [i]+[u]。
- `oe` 是 [ø]，不是 [o]+[e]。
- `on` 是 [oŋ]，不是 [on]。
- `aon` 是鼻化元音 [ɑ̃]，不是 [a]+[o]+[n]，也不能一律替换成后鼻音 [ɑŋ]。
- `en/in` 的中派表为 [ən]/[in]，老派表列 [əŋ]/[iŋ]；本地词典 IPA 中常见后者，属于必须保留的版本/记音差异。
- `er` 是一个韵母；官网“而”写 `gher6`，[ɦəl²³]，不能由此给本地所有裸 `er` 自动增加 gh。

## 4. 调类号、词典调值与录音五度值必须分开

公开方案和官网单字查询使用下列上海中派对应关系：[1][2]

| 官网吴拼末尾数字 | 调类 | 该方案单字调值 |
|---:|---|---:|
| 1 | 阴平 | 53 |
| 5 | 阴去 | 34 |
| 6 | 阳舒 | 23 |
| 7 | 阴入 | 5 |
| 8 | 阳入 | 12 |

这些号码不是本轮 F0 的五档等级。例如官网 `shiau5` 的 5 是调类号，该页 IPA 另写 34；`ghoq8` 的 8 是调类号，IPA 调值为12。老派还列3号阴上，且5号的调值为35、6号为13、7号为4；松江有其独立八调表。因此即使确定某后缀是调类，也必须先知道哪一版音系，不能统一套上海中派数值。

本地最后一列的三个例子则是：

| 本地CSV记录行（从1计，含第一行数据） | 词条 | 最后一列 | 声韵解析与数字的处理 |
|---:|---|---|---|
| 7923 | 小学 | `shiau33 ghoq4` | `sh+iau`、`gh+oq`；33与4按词典调值候选保存，不能当成官网调类号。 |
| 1449 | 辰光 | `zen22 kuaon44` | `z+en`、`k+uaon`；22与44按词典连读调值候选保存。 |
| 7918 | 班主任 | `pe55 tsy33 zen21` | `p+e`、`ts+y`、`z+en`；55/33/21均不是官网单字调类号码。 |

这里的“调值候选”只表示词典后缀的记法判断，尚未查到这份 CSV 转换历史的完整说明，不能断言它们是某位作者逐词实测值。尤其不能说这次录音的“学”应强制为4，或用这些数字约束音素对齐后再当作声学验证。

### 本地文件存在少量混用

本轮只读检查得到21,021条CSV记录；文件没有常规表头，第一行是数据，且第一列为“内”、第二列为“【黄胖日头】”，不能误删为表头。后缀中22、55、33、21等最常见，但以下4条记录含6/7/8：

| 记录行 | 词条 | 最后一列原文 |
|---:|---|---|
| 520 | 呒头苍蝇 | `m2deu6tshaon1in1` |
| 7321 | 清水光汤朋友 | `chin1sy5kuaon1thaon1ban6yeu6` |
| 7624 | 宝宝子，肉肉子 | `pau5pau5tsy5gnioq8gnioq8tsy5` |
| 13146 | 一方面……一方面…… | `iq7faon1mi6iq7faon1mi6` |

6/7/8不属于五度音高数字，提示这些行仍含调类式记法。第一条还出现2，不能强行套到仅有1/5/6/7/8的中派表，须查源记录。其他只有单数字1至5的项，也不能仅凭位数自动判断是调类还是入声调值。

建议记录 `tone_suffix_raw`、`tone_notation`、`tone_source` 三列，状态可为 `contour_candidate`、`category_candidate`、`mixed_or_uncertain`。本轮声韵候选转换可以暂不使用声调后缀，但必须将原后缀无损保留在旁列。

## 5. 词典声韵与IPA不能无条件互相覆盖

对“辰光”，公开中派方案解析 `zen` 为 [zən]，本地IPA列写 [zəŋ]；“班主任”末字也有同样差异。中派与老派韵尾记法不同，以及不同词典对音系的处理，都可能影响结果。不能默认网站方案比本地词典更适合录音，也不能只凭本地IPA列存在就认为它与最后一列严格对应。

另有更直接需要复核的例子：本地第12条“飓风”最后列为 `jiu22 fon44`，按中派方案 `jiu` 的韵母 iu 为 [y]，但本地IPA列为 `dʑu foŋ`。这是 [y] 与 [u] 的不一致，应保存两边、标记来源冲突；没有听校和来源依据时不擅自把其中一边修成另一边。

本地第三列的旧拼写与最后一列也不能混解：例如“学”旧式出现 `hhok`，最后列是 `ghoq`。前者的 h/k 规则不应混入本轮按学堂式解析最后一列的规则。分隔符缺失、斜杠、括号、多读、轻声或词条内标点也都要保留来源。

## 6. 建议的安全转换流程

1. **锁定来源**：保存文件路径、哈希、行号、原词头、最后一列原文、原IPA列；本轮原件SHA-256为 `cbfee5e55987098fda08ff85547671f66f615af31b45bd3f5738dfd1f8407ce5`。若用户继续修改原件，应另记新哈希，不能把旧结果当同一版本。
2. **先切音节候选**：兼容空格和紧连拼写；利用“字母串＋连续数字后缀”的形式辅助分段，但检查是否完整覆盖原串。括号、斜线、多读和无调号项应单独标记，不吞掉未解析字符。
3. **分离数字**：声韵主体与 `tone_suffix_raw` 分开，不在未确认记法时将后缀转成IPA调号或模型音素。
4. **按版本解析完整音节**：使用最长合法声母匹配和韵母表，另外处理 y/w 的条件拼写以及独立m/n/ng。`gn/ng`、`sh/zh`、`gh`、`tsh`、`iu/oe/aon` 均不能逐字母替换。
5. **产出有出处的IPA候选**：为每条保存 `scheme=学堂式_上海中派_所查版本`、解析出的声母/韵母、IPA候选和规则来源；超出该表的拼写标 `unknown_spelling`，不猜补。
6. **与原IPA并列审阅**：相符可标 `scheme_consistent`，不同标 `source_conflict` 或 `variant_possible`。所有候选仍需结合当前说话人的实际口音与词中读音听校。
7. **另做模型phone映射**：IPA候选不是MFA/CTC模型能直接吃的标签。逐项核对模型 phone set，显式记录ȵ、ᴀ、ᴇ、鼻化、成音节符号、送气和声门成分怎样处理；关键音未覆盖时先停止该项自动转换，而不是删符号凑词表。
8. **保留汉字映射**：词条→音节→字的对应不由数量相等自动决定。省音、合音、儿缀和多字词的变调/白读需要显式关系。完成读音层后再走13号笔记中的音频强制对齐和人工边界验证。

上述三个例子的**方案IPA候选（暂不编码词典声调）**分别为：

```text
小学    shiau | ghoq          → ɕiɔ | ɦoʔ
辰光    zen | kuaon          → zən | kuɑ̃
班主任  pe | tsy | zen       → pᴇ | tsɿ | zən
```

其中 en 与本地IPA的 [əŋ] 差异必须同时显示，不能默默替换。这里输出的是根据已查方案生成的读音候选，不是已完成的声学音素序列、音频时间边界或这段录音的实际调值。

可机读表已保存为 `generated/recording_11_20260909/tone_pilot/alignment_diagnostics/wugniu_scheme.json`：33项声母（含零声母）、43项韵母已逐项与缓存原表比较；另有独立成音节鼻音、gh/y/w条件拼写展开、10个解析例子和来源字段。条件拼写展开是把原文规则变为程序输入的实现候选，未逐音节向官网查证。裸 `u` 及 `ua/uen` 等合法韵母按零声母处理，不自动增加 w 或 [ɦ]；独立 `m/n/ng` 必须在普通声母切分前识别。
